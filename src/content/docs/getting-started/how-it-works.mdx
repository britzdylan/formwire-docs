FormWire is a backend for the forms on your site. You point a form at a FormWire endpoint, and FormWire receives each submission, scores it for spam, validates it, stores it, notifies you, and forwards it to other tools. You don't run a server or a database.

This page explains the concepts the other pages rely on.

## Forms

A **form** in FormWire represents one form on your site. You create it in the dashboard, and FormWire gives it:

- A **form secret**, which is a random identifier.
- A **submission endpoint** that contains the secret.
- Settings, including a redirect URL, a success message, a submission limit, a validation schema, and notifications.

Every plan allows unlimited forms. Each form stores its own submissions.

## The submission endpoint

Every form has one endpoint:

```txt
POST https://api.formwire.app/v1/submit/YOUR_FORM_SECRET
```

The endpoint has no authentication, because your visitors' browsers call it directly. The secret in the URL tells FormWire which form a submission belongs to. Anyone who has the secret can submit to the form, so it is safe to put in your frontend code but not truly private.

If someone abuses the secret, you can regenerate it in the form's settings. The old endpoint stops working immediately.

The endpoint accepts two content types:

- **`application/x-www-form-urlencoded`** is what a plain HTML `<form>` sends. If the form has a redirect URL, the visitor is redirected there after submitting.
- **`application/json`** is what you typically send with `fetch`. The response is JSON.

A submission can be at most **50&nbsp;KB**, and it must contain at least one field. Each visitor IP address can send up to 30 requests per minute to a form.

## What happens to a submission

FormWire processes each submission in this order:

<Steps>

1. **Form lookup.** The secret is matched to a form. An unknown secret is rejected.
2. **Enabled check.** A disabled form rejects the submission.
3. **Limit checks.** The form's own submission limit and your plan's monthly quota are checked.
4. **Spam analysis.** The honeypot, timing, and content checks produce a spam score. See [Spam Protection](/guides/spam-protection).
5. **Sanitization.** The submitted values are cleaned.
6. **Schema validation.** If the form has a schema, the data is checked against it. See [Schema Validation](/guides/schema-validation).
7. **Metadata capture.** Details about the request are recorded, as described below.
8. **Storage and delivery.** The submission is saved, notifications are sent, and the form's integrations run.

</Steps>

A submission that is rejected in steps 1 to 3 is not stored. Once a submission passes those checks it is always stored, even if it is spam or fails validation.

## Submission status

Every stored submission has a status. FormWire sets the first three automatically from the spam score and the validation result. You set the others yourself.

| Status | When it applies |
| --- | --- |
| <Badge text="new" variant="success" /> | The submission is clean and passed validation, or the form has no schema. |
| <Badge text="pending_review" variant="caution" /> | The spam score is 31 to 60, or validation failed. |
| <Badge text="spam" variant="danger" /> | The spam score is 61 or higher. |
| <Badge text="read" variant="note" /> | You opened it in the dashboard. Opening a `new` submission marks it as read. |
| <Badge text="archived" /> | You archived it. |
| <Badge text="rejected" variant="danger" /> | You rejected it. |

You can search by status and change a submission's status in the dashboard. See [Submissions](/guides/submissions).

## Captured metadata

FormWire stores these details with each submission:

- **Source.** The IP address, user agent, referrer, and request origin. FormWire derives an approximate location (country, region, city, timezone) from the IP address, and the device, browser, and operating system from the user agent.
- **UTM parameters.** `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, and `utm_content`, read from the referrer URL when present.
- **Validation.** Which fields passed, which failed, and which were not in the schema.
- **Security.** The spam score, the signals that raised it, and the honeypot and timing results.

You can see all of this on each submission's detail page.

FormWire gives every submission a spam score when it arrives. The score sets the submission's status, which keeps spam out of your `new` submissions and stops it from being forwarded to your integrations.

Content analysis runs on every submission. The honeypot and timing checks only work after you add a field for each one to your form.

## How scoring works

Each submission starts with a score of 0. These signals add to it:

| Signal | Points | What triggers it |
| --- | --- | --- |
| Honeypot | +80 | The `_fw_hp` field has a value. |
| Timing | +40 | The form was submitted less than 2 seconds after it loaded. |
| Malicious content | +40 to +80 | A field contains an attack pattern, such as SQL injection or cross-site scripting. |

The score can't go above 100. It sets the submission's status:

| Score | Spam status | Submission status |
| --- | --- | --- |
| 0 to 30 | `clean` | <Badge text="new" variant="success" />, if the submission also passes validation |
| 31 to 60 | `suspicious` | <Badge text="pending_review" variant="caution" /> |
| 61 to 100 | `confirmed_spam` | <Badge text="spam" variant="danger" /> |

:::note[Spam is stored, not discarded]
FormWire stores submissions marked as `spam` so that you can review them and recover anything that was flagged by mistake.
:::

## Honeypot field

A honeypot is a field that people can't see and bots tend to fill in. Add a field named **`_fw_hp`** to your form and hide it with CSS. Don't use `type="hidden"`, because some bots skip hidden inputs.

```html
<input
  type="text"
  name="_fw_hp"
  tabindex="-1"
  autocomplete="off"
  style="position: absolute; left: -9999px"
  aria-hidden="true"
/>
```

A submission with any value in this field gets 80 points, which is enough to mark it as spam. FormWire removes `_fw_hp` before it stores the submission.

## Timing check

Bots usually submit a form the moment it loads, and people take longer. Add a field named **`_fw_loaded`** and set it to the time the form loaded, as a timestamp in milliseconds:

```html
<input type="hidden" name="_fw_loaded" value="" />
<script>
  document.currentScript.previousElementSibling.value = Date.now();
</script>
```

A submission that arrives less than 2 seconds after that time gets 40 points. FormWire removes `_fw_loaded` before it stores the submission.

:::caution[Framer]
The timing check doesn't work with Framer's built-in forms, because Framer sends those submissions from its own servers and you can't add the load time as a field. It works when you build the form as a Framer Code Component that posts to FormWire directly. See the [Framer guide](/frameworks/framer#timing-check).
:::

## Malicious content

FormWire checks every submitted value for attack patterns. The points depend on how severe the pattern is:

| Pattern | Points |
| --- | --- |
| Path traversal | +40 |
| SQL injection, cross-site scripting, or script injection | +60 |
| Command injection | +80 |

If a submission matches more than one pattern, the highest value applies and each additional match adds 10 points. The matches are listed in the submission's security details.

## Review flagged submissions

Search a form's [submissions](/guides/submissions) for a status to see what was flagged:

- <Badge text="pending_review" variant="caution" /> submissions are borderline and worth checking.
- <Badge text="spam" variant="danger" /> submissions scored 61 or higher.

If a real message was flagged, open it and change its status.

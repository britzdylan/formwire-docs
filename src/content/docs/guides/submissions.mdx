FormWire stores every accepted submission with its form data and the metadata it captured. This page explains how to work with submissions in the dashboard.

## Find submissions

Open a form and go to its **Submissions** tab to see everything that form has received. Use the search box to narrow the list. Search matches the submitted values, the status, the spam status, and the country, so searching for `spam` shows the submissions with that status.

## Submission status

FormWire sets a submission's first status when it arrives. You can change the status afterward.

| Status | Meaning |
| --- | --- |
| <Badge text="new" variant="success" /> | The submission is clean and valid, and you haven't opened it yet. |
| <Badge text="pending_review" variant="caution" /> | The spam score is 31 to 60, or the submission failed schema validation. |
| <Badge text="spam" variant="danger" /> | The spam score is 61 or higher. |
| <Badge text="read" variant="note" /> | You opened it. Opening a `new` submission marks it as read. |
| <Badge text="archived" /> | You archived it. It stays stored. |
| <Badge text="rejected" variant="danger" /> | You rejected it. |

To change a status, open the submission and use **Set status**.

## Submission details

Opening a submission shows four groups of information:

- **Data** is the submitted fields.
- **Validation** shows which fields passed, which failed and why, and which fields were not in your schema.
- **Security** shows the spam score, the signals that raised it, and the honeypot and timing results.
- **Source** shows the IP address, user agent, referrer, origin, approximate location, device and browser, and any UTM parameters.

## Delete a submission

:::danger
Deleting a submission is permanent. [Export](/guides/exporting-data) it first if you need a record.
:::

## Retry a failed integration

If an [integration](/integrations) failed to deliver a submission, open the submission and click **Retry failed**. FormWire sends the submission again to the integrations that failed. Integrations that already succeeded are not called again.

Integrations only deliver submissions whose status is `new`. If the delivery failed because the submission was flagged as spam or pending review, set its status to `new` before you retry.
